# Flagstar — Consent Vault + Third-Party Access Gateway

**Project Title & Description**
**“Consent Vault & Third-Party Access Gateway”** — A platform that stores customer consent (capture/version/expiry/revocation) and acts as a policy gate in front of APIs so third-party fintech apps only access data the customer explicitly allowed, with full audit trails.

**Interview phrasing**
“At Flagstar, I was part of a team that built a Consent Vault and API access gateway so third parties could only access customer banking data when valid consent existed, using Spring Boot, Spring Security (OAuth2/JWT/RBAC), REST APIs, and AWS.”

**Why It Fits the Resume**

* Directly matches Dylan’s **Customer Consent & Data Privacy Management Platform** work (consent lifecycle + auditability + Open Banking-style integrations).
* Showcases **OAuth2/JWT/RBAC**, regulatory-driven design, and secure REST integration.

**STAR Talking Points (prompts)**

* **Situation:** What compliance or security gap existed (e.g., third-party data sharing lacked consistent enforcement)?
* **Task:** What was required (centralized consent + enforceable API checks + audit reporting)?
* **Action:** What you built personally (consent model, consent validation middleware, audit events, token scopes/roles, endpoints).
* **Result:** What improved (reduced unauthorized access risk, faster audits, fewer manual compliance checks).
